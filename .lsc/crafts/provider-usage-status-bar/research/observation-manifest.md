## Facet A — Anthropic subscription (Pro/Max) 5-hour + 7-day usage acquisition

- **[ResOAuthSubUsage] [OFFICIAL]** Claude Code statusline stdin exposes `rate_limits.five_hour.{used_percentage,resets_at}` and `rate_limits.seven_day.{used_percentage,resets_at}` (used_percentage 0–100; resets_at Unix epoch). Server-provided, NOT local token inference. Present ONLY for Claude.ai Pro/Max subscribers, and only AFTER the first API response; each window can be independently absent. Source: https://code.claude.com/docs/en/statusline . Landed in Claude Code v2.1.80 (CHANGELOG). [ResAnthropicUsage corroborates]
- **[ResOAuthSubUsage] [OFFICIAL]** Agent SDK `AccountInfo` fields: `email`, `organization`, `subscriptionType`, `tokenSource`, `apiKeySource`. The one DOCUMENTED account-identity/tier surface. Source: https://code.claude.com/docs/en/agent-sdk/typescript . `/status` Login-method row shows the subscription account; `/login` writes local credential stores (IAM docs).
- **[ResAnthropicUsage / ResRepoDiveUsage / ResPriorArtUsageTools / ResOAuthSubUsage] [UNOFFICIAL — but empirically working, multi-source]** `GET https://api.anthropic.com/api/oauth/usage`, headers `Authorization: Bearer <claudeAiOauth.accessToken>`, `anthropic-beta: oauth-2025-04-20`, `User-Agent: claude-code/<version>`. Response JSON: `five_hour{utilization,resets_at}`, `seven_day{utilization,resets_at}`, `seven_day_sonnet{...}`, `seven_day_opus` (nullable), `extra_usage{is_enabled,monthly_limit,used_credits,utilization}`. utilization 0–100 (some clients see 0..1 and normalize). Server-side/cross-device authoritative. Frequent **429** unless correct UA + poll ≥180s + cache. Requires OAuth scope `user:profile`. Independently observed by ≥5 OSS tools: aiedwardyi/claude-usage-monitor (statusline.py), ohugonnot/claude-code-statusline, pcvelz/ccstatusline-usage, fredrikaverpil/claudeline (internal/usage/usage.go), Maciek-roboblog/Claude-Code-Usage-Monitor (output/api_usage.py), steipete/CodexBar (ClaudeOAuthUsageFetcher.swift). Official acknowledgement of the endpoint path + 429 in claude-code issues #30930, #31021, #40094, #13585.
- **[ResAnthropicUsage] [UNOFFICIAL]** Unified rate-limit RESPONSE HEADERS on `POST /v1/messages`: `anthropic-ratelimit-unified-{5h,7d}-{status,remaining,reset,utilization}`, `anthropic-ratelimit-unified-representative-claim`. Obtainable opportunistically from calls the host already makes. CodexBar issue #1894 (Jul 2026) measured them distinct across 4 subscription accounts; `user:inference` scope suffices, but a minimal POST costs ~1 output token; `count_tokens` lacks these headers; `oauth/usage` (needs `user:profile`) returns 403 for a setup-token. Sources: claude-code issues #12829, #55333; CodexBar #1894.
- **[ResAnthropicUsage] [OFFICIAL — negative result]** Anthropic Admin Usage & Cost API (`GET /v1/organizations/usage_report/messages`, group_by/filter `account_id`/`api_key_id`, buckets 1m/1h/1d, ~5min delay; `cost_report` 1d only) exposes historical token/cost per account but NOT 5h/7d plan utilization or resets — 1m buckets can only be summed as a PROXY. Requires org Admin key, unavailable to individual accounts. `anthropic-ratelimit-*` (RPM/ITPM/OTPM token-bucket) headers are API-key limits, NOT subscription 5h/7d. Sources: platform.claude.com/docs/en/api/rate-limits, /manage-claude/usage-cost-api, /manage-claude/rate-limits-api. Official issue #44328 / #13585: no supported public `claude usage --json` / quota REST endpoint exists (feature requests, closed/open).
- **[ResAnthropicUsage] [OFFICIAL — semantics]** Pro/Max: a **5-hour session limit** (resets every 5h) + a **weekly limit** with a FIXED account-assigned reset time each week (Max has two weekly buckets: all-models + Sonnet-only; Opus-specific limit may also exist). Subscription quota is ACCOUNT-WIDE across web/desktop/mobile/Claude Code/IDE; API-key auth bills separately. Visible in Settings>Usage / `/usage`. Sources: support.claude.com articles 8325606 (Pro), 11049741 (Max), 9797557, 11145838, 11647753.

## Facet B — OpenAI / Codex subscription usage acquisition

- **[ResPriorArtUsageTools] [UNOFFICIAL]** Codex uses internal `GET https://chatgpt.com/backend-api/wham/usage`. AgentLimits `CodexUsageFetcher` parses `rate_limit.primary_window` and `rate_limit.secondary_window` with fields `used_percent`, `limit_window_seconds`, `reset_at` — primary ≈ 5-hour, secondary ≈ weekly. Menu bar shows X%/Y% (5h/weekly). Source: https://github.com/Nihondo/AgentLimits .
- **[ResOpenAIUsage — pending formal report]** Official OpenAI rate-limit headers `x-ratelimit-{limit,remaining,reset}-{requests,tokens}` reflect short RPM/TPM windows, not a 5h/weekly subscription analog (to be confirmed in formal report).

## Facet C — API-key vs subscription boundary (hard capability limit)

- **[ResPriorArtUsageTools / ResOAuthSubUsage] [convergent]** Subscription 5h/7d quota is obtainable ONLY for OAuth/subscription (Pro/Max/Team) accounts. **API-key accounts, Enterprise, and Bedrock have NO subscription rate-limit display** — tools explicitly hide usage bars for them (claude-hud, claudeline READMEs; CodexBar flags API-key rows "subscription usage unavailable"). API-key usage can only be approximated via local token/cost accounting, which ccusage #658 states is NOT meaningful as a subscription-quota proxy.
- **[ResRepoDiveUsage] [convergent]** Local-log inference (ccusage/ccmonitor) reconstructs windows from `~/.claude/projects/**/*.jsonl` token accounting — 5h "blocks" floored to the hour, weekly = calendar-week bucket — with NO server reset times and hourly granularity; cannot capture cross-device usage. A strictly weaker fallback than the server quota fields.

## Facet D — Multi-account handling prior art

- **[ResRepoDiveUsage] Maciek-roboblog/Claude-Code-Usage-Monitor** buckets usage by `(source.kind, source.account)`, runs each source independently, block IDs suffixed `|kind:account`; `UsageWarehouse` dedups by SHA256(source kind+account, timestamp, project, model, message_id, request_id); `query_daily` groups by `source_account`. Caveat: for local JSONL, "account" = the config-dir provenance PATH, not OAuth identity.
- **[ResRepoDiveUsage] steipete/CodexBar** consumes an external account manager `claude-swap` (`cswap --list --json`, schema v1): returns active-account number + account slots, each with per-account `usageStatus` (five-hour/7-day pct + resets). Identity = `claude-swap:<slot>` (not email). Up to 4 status items; stale snapshot retained; API-key rows flagged subscription-usage-unavailable. Machine-readable per-account subscription usage WITHOUT local token counting. Source: CodexBar docs/claude-multi-account-and-status-items.md + ClaudeSwapAccount*.swift.
- **[ResRepoDiveUsage] opencode** persists per-subscription counters in SQL keyed by `workspaceID+userID` (atomic increments), distinct from an API-key rate limiter (Redis key `${stage}:ratelimit:key:${apiKey}:${model}-${YYYYMMDDHHmm}`, 60s).

## Facet E — Persistent bottom-footer rendering prior art

- **[ResTuiFooterPriorArt] nicobailon/pi-powerline-footer** — a **Pi coding-agent EXTENSION** (TS), the closest platform analog. Renders a fixed bottom cluster (status/editor/secondary/transcript lines) below the editor via a DIRECT ANSI compositor: `fixed-editor/terminal-split.ts buildFixedClusterPaint` reserves bottom rows (`startRow = terminalRows - cluster.lines.length + 1`), sets the terminal scroll region `top..rawRows-reservedRows`, repaints the cluster, uses synchronized-output CSI `?2026h/l` + alternate screen; `render-scheduler.ts` coalesces with debounce (STATUS 33ms / CONTEXT 250ms / EDITOR 150ms). **Custom extension status keys can be dedicated items** → extensions contribute status content. Multi-row + truncation supported. Source: https://github.com/nicobailon/pi-powerline-footer .
- **[ResTuiFooterPriorArt] Gemini CLI (Ink/React)** — `<Footer/>` rendered persistently directly below `<InputPrompt/>` in a column `Box`; `QuotaChanged` event-driven refresh; width-fitting iterates columns by priority, truncates/drops over-budget with `…`. Source: google-gemini/gemini-cli Composer.tsx/Footer.tsx/QuotaDisplay.tsx.
- **[ResTuiFooterPriorArt] OpenTUI** (`CliRenderer`, Zig core + TS) — `screenMode: 'split-footer'` pins a reserved footer region at the terminal bottom (`footerHeight` default 12), captures stdout and replays it above the footer, emits scrollback+footer as one atomic ANSI frame; targetFps 30/maxFps 60, rerenders on tree change. Directly solves persistent-bottom-region without disrupting input. Source: https://opentui.com/docs/core-concepts/renderer/ .
- **[ResTuiFooterPriorArt] opencode TUI** (@opentui/solid) — multi-row persistent prompt region (textarea + metadata + status + right-side context/cost). Plugin footer SLOTS exist (`home_footer`, `sidebar_footer`, `session_prompt`, `session_prompt_right`) but **NO generic session-footer slot**; a persistent plugin status-bar-widget API is an UNSHIPPED proposal (issue #23539). Caution: plugin-contributed footers are not universally available across hosts.

## Facet F — Reset/window semantics & risk flags

- **[ResAnthropicUsage]** seven_day may carry MULTIPLE buckets (all-models / sonnet-only / opus-only), some nullable, version/plan-dependent. Implementation must preserve unknown optional buckets, not assume a single `seven_day`.
- **[ResAnthropicUsage] [UNVERIFIED — flagged discrepancy]** monperrus gist claims seven_day utilization drops ~every 72h while resets_at points ~7d ahead (fixed ~04:50 UTC anchor) — CONFLICTS with official "fixed account-assigned weekly reset". Treat as anecdotal; use server `resets_at`/Settings>Usage as authoritative.
- **[ResAnthropicUsage / ResRepoDiveUsage]** oauth/usage 429 mitigation is load-bearing: correct `User-Agent`, poll ≥180s, cache with TTL (60–180s across tools), serve-stale on error, honor `Retry-After` (seconds or date).
- **[ResPriorArtUsageTools]** canonical merge order (ccstatusline-usage, claudeline, claude-hud): prefer NATIVE server-provided fields, API-fetch only missing fields, fall back to local JSONL blocks ONLY when server reset is absent.
