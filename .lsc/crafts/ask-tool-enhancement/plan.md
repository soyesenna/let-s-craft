## 0. Context — 소비 계약 및 확정 사실 (리뷰어 필독)

trace가 확정한 4계층(§7): (a) 좁힘 3지점 widening + (b) 자유입력 조합 패턴 + (c) 소비자 co-evolution(critical path) + (d) 품질 규칙의 지시 계층 인코딩. 소스 재탐사 + 리뷰 검증으로 설계를 좌우하는 사실 5건을 확정했다:

**(F1) multi-select는 단일 프리미티브가 아니라 `ctx.ui.select` 재호출 루프다.**
확장 표면의 `ExtensionUIDialogOptions`는 `selectionMarker: "radio"|"checkbox"`(`node_modules/@oh-my-pi/pi-coding-agent/src/extensibility/extensions/types.ts:148`), `checkedIndices`(`:150`), `markableCount`(`:154`, trailing 제어행은 마커 제외, 주석 `:151-153`)를 지원하지만 이는 **렌더링 제어**일 뿐이고, select는 매 호출마다 활성화된 행 라벨 1개를 반환한다. 같은 버전(16.4.0) SDK의 내장 ask 도구가 multi를 정확히 **루프**로 구현한다: checked 집합에서 `checkedIndices` 재구성 → `selectOption(...)` 재호출 → 토글 반복, Other 행 선택 시 custom input 진입(`node_modules/@oh-my-pi/pi-coding-agent/src/tools/ask.ts:526-578`). **Done 제어행은 `selected.size > 0`일 때만 append된다**(`tools/ask.ts:529-531` — Done을 먼저, Other를 마지막에 push `:532`). 이 루프 패턴을 `ctx.ui.select` + `initialIndex`(커서 복원)로 그대로 이식한다 — bespoke 위젯 불요.

**(F2) `ctx.ui.select`는 index가 아니라 "선택된 표시 label 문자열"을 반환한다** — "Show a selector and return the selected label, even when an option also includes a description"(`extensibility/extensions/types.ts:185-190` doc + 시그니처; `ExtensionUISelectOption = {label, description?}` `:110-114`). TUI 콜백도 label만 넘긴다(`modes/components/hook-selector.ts:248-249, 660-661` — `onSelectCallback(selected.option.label)`). 따라서 " (Recommended)" 접미사가 붙은 **표시 라벨이 그대로 반환**되고, 해석은 인덱스 역매핑이 아니라 **표시 라벨 → 정본(canonical) 라벨 lookup**이다. 이 lookup이 안전하려면 접미사·제어행 적용 **후** 최종 표시 라벨 집합의 유일성이 검증되어야 한다(§4 DR-D6 — `"A"`+`"A (Recommended)"` 변환 후 충돌 클래스). `ctx.ui.editor(title, prefill?, ...)`는 멀티라인 모달로 실재(`types.ts:248-253`).

**(F3) 기존 E2E가 lsc_confirm의 content 텍스트를 직접 단언한다.**
`test/enforcement-rules.test.ts:198-200`(`confirm?.text.trim().toLowerCase()==='no'`), `:369-371`(`==='yes'`). 따라서 confirm 재구성 후에도 **boolean 답의 content는 정확히 `yes`/`no` 단독 1행을 유지**한다(§4 DR-D2). 같은 파일의 인라인 fixture JSON 2곳(v1 body `:153-156`, `:336-339`; 두 번째는 test-local `[Release]` 태그 — 규칙 `:338`과 프롬프트 발문 `:350-351` 모두 `[Release]`이며 craft SKILL의 `[Canon Amendment]` 게이트와 무관, 의도 주석 `:330-333`)은 v2 클린 컷 시 **반드시 동시 이관**해야 한다(누락 시 v2 파서가 hard error → E2E 전면 파손, §6 프리모템 P2).

**(F4) 옵션 상한 2-4는 compact 모드 확률을 낮출 뿐, 배제하지 않는다.** (iter 1의 "구조적 회피" 서술은 실측 반증되어 교체)
extension UI 경로는 `maxVisible`을 기본값이 아니라 **매 호출 터미널 크기로 명시 주입**한다: `maxVisible = Math.max(4, Math.min(15, terminal.rows - 12))`(`modes/controllers/extension-ui-controller.ts:604`). compact(커서 옵션만 description 표시) 판정 기준은 옵션 개수가 아니라 **wrap된 description을 포함한 총 렌더 행 수 > maxVisible**이다(`modes/components/hook-selector.ts:491-500` — `#updateList`의 `compact = #isSearchEnabled(...)`; `:593-595` — `#totalOptionRows(...) > #maxVisible`). 즉 옵션 4개여도 WHAT/WHY/장단점 4-6행 description이거나 작은 터미널이면 compact가 발동하며, 그 경우에도 커서 이동으로 각 옵션의 description을 열람할 수 있다(전면 소실 아님). R10(2-4 강제)은 불변 — 근거는 "compact 발동 확률·심도 축소 + 인지 과부하 상한"으로 교체하고, compact 발동 케이스를 TUI 스모크에 추가한다(Step 4).

**(F5) `AgentToolResult.details`는 모델에게 전달되지 않는다 — 모델-facing 결정 계약은 content가 유일 채널이다.** (iter 2 신규 확정 — 리뷰 2건 수렴 + 독립 재검증)
계약 정의부터 "Details to be displayed in a UI or logged"(`node_modules/@oh-my-pi/pi-agent-core/src/types.ts:547-553`)이고, provider 직렬화도 Anthropic은 `msg.content`만 tool_result 블록으로(`node_modules/@oh-my-pi/pi-ai/src/providers/anthropic.ts:3373-3393`), OpenAI Responses도 `toolResult.content`의 text만 join해(`openai-shared.ts:1614-1628`) 전송한다. SKILL.md를 실행하는 모델에게 `details`는 존재하지 않는다. 따라서 **게이트 분기 규칙은 content envelope(1-C)로 작성**하고, `details`는 테스트/UI/이벤트 관측용 구조 정본으로 유지한다. 관측 경로는 실재한다: `tool_execution_end` 이벤트는 두 emit 지점 모두 `details: result.details`를 보존한다(`node_modules/@oh-my-pi/pi-coding-agent/src/cursor.ts:97-101`, `:302-312`) — 단 현행 E2E helper `toolExecutions`는 content 텍스트만 추출하므로(`test/e2e-helpers.ts:275-285`) details 단언에는 helper 확장이 필요하다(Step 4).

**변경 표면 재확인(현재 소스):** zod 스키마 `src/ask.ts:250-253/269-272/287-289`(select options는 `z.array(z.string()).min(2)` `:271`), UI 포트 `AskUI :46-48`/`SelectUI :84-86`/`ConfirmUI :186-188`, `resolveSelectOption :120-134`, 반환 계약(성공 = `content[{type:"text"}]`+`details{question, response|confirmed, source:"fixture"|"ui"}`; 실패·취소 = `isError:true`+content만) — performAsk `:50-72`, performSelect `:136-174`, performConfirm `:198-229`. fixture 결합면 = `FixtureMatch{response, optionIndex?}`(`src/fixtures.ts:87-90`)를 `channel.answers.match()`로 소비(`src/ask.ts:60,146,208`). 진입점 `src/main.ts:23 registerAskTools(pi)`. vitest는 omp SDK 값을 import할 수 없다(`src/ask.ts:12-15` 헤더 주석, Phase 1.5 실측) — AC1 검증 메커니즘 설계의 전제(§4 DR-D7). - **채널 공통 preflight(iter 4·iter 5 순서 정밀화)**: 위 select 시맨틱 검증 전부(label 형식·예약어·정본/표시 중복·recommended 범위·description 실질성)는 `performSelect`가 **unavailable fail-closed 처리 후, fixture/UI dispatch 전**에 `validateSelectOptions`로 실행 — fixture 경로(=E2E)도 동일 가드·동일 isError를 통과하고(1-C/1-D, P0-H), 채널 자체가 없는 headless hard error 진단은 현행대로 최우선을 유지한다(Minor-1).
- `approval: "read"` 3곳(`src/ask.ts:262,280,296`) **유지** — 도구 부작용 표면 불변(사용자 입력 수집만; editor도 read-급 모달). §5 ADR Consequences에 기록.
- **원자적 cutover 커밋**: v1/v2는 비호환이므로 green 검증·커밋 경계는 §2 서두의 단일 cutover 규칙을 따른다(Principle 2).

  - confirm(boolean): content는 **정확히 `yes` 또는 `no` 단독** — 어떤 텍스트도 병기하지 않는다. 결정 판정은 `content.trim()`의 전체 일치로만.
  - 선택(select): **선택당 `User selected: ${정본 라벨}` 1행 반복**(행 순서 = options 배열 순서 — 결정적 직렬화). 콤마 결합 단일 행(iter 2안)은 폐기 — `["Alpha Team, Beta Team","Gamma Group"]`과 `["Alpha Team","Beta Team, Gamma Group"]`이 동일 content를 만드는 비단사 반례(A/C 수렴). **택1 근거(vs `User selected: [JSON 배열]`)**: 행 반복은 기존 header 토큰·E2E 텍스트 단언 형태를 유지하고 D2가 기각한 JSON-in-content를 재도입하지 않으면서, single-line label 가드와 결합해 "행 경계 = 선택 경계"의 무손실 표현을 달성한다(critic 권장안과 합치; JSON 배열도 무손실이나 가독성·벤더 관례에서 열위 — D2).
  - 자유답변(select·confirm): content가 `FREE_ANSWER_SENTINEL`로 시작하는 **top-level 행 1개**. **freeText line-break 정규화 — `canonicalizeFreeText()`(iter 4 — P0-G①·iter 5 규범 집합화/단일 소유 — P0-J/P0-K)**: 직렬화·저장 전에 freeText의 line-break를 canonical `\n`으로 정규화한다. 대상 집합은 수기 code-point 목록이 아니라 **규범 참조로 정의한다 — UAX #14 mandatory break 계열(`Line_Break ∈ BK∪CR∪LF∪NL`) 7종: LF(U+000A)·VT(U+000B)·FF(U+000C)·CR(U+000D)·NEL(U+0085)·LS(U+2028)·PS(U+2029)**(이하 "mandatory break 7종"; Unicode `LineBreak.txt` `000B..000C;BK` — iter 4의 수기 5종 목록은 `Line_Break=BK`인 VT/FF를 빠뜨려 interior VT/FF label·freeText가 가드·판별을 통과했다, A r4 BLOCKING·C r4 Major 1 수렴). 접기 규칙: **CRLF(`\r\n`)를 쌍당 1개의 `\n`으로 먼저 접은 뒤**, 잔여 6종(bare CR·VT·FF·NEL·LS·PS)을 각각 `\n` 1개로 치환한다(멱등 — `f(f(x)) === f(x)`). **단일 소유(P0-K)**: 이 함수는 `canonicalizeFreeText(text: string): string` pure helper로 **`src/fixtures.ts`가 export하고 `src/ask.ts`가 import해 재사용한다** — 현행 의존 방향 ask→fixtures(`src/ask.ts:17`)를 보존해 ESM cycle 0·정규식 중복(UI/fixture parity drift) 0(중립 모듈 신설 대안은 기각 — 순수 함수 1개를 위해 Scope 파일을 늘릴 이유가 없고 의존 하단 배치가 동일 효과). 차용 벤더 구현은 `includes("\n")`/`split("\n")` **LF-only**라(`tools/ask.ts:871-876` 실측) 그대로 이식하면 bare CR·유니코드 분리자 payload가 들여쓰기를 우회한다. **단일행/멀티라인 판별 기준**: canonical `text`에 `\n`이 없으면 인라인 1행 `User provided free answer: ${text}`, 있으면 sentinel 단독 행 + canonical 행 전부 2-스페이스 들여쓰기(벤더 O57 차용). **들여쓴 payload는 opaque** — payload 행이 `User selected:`/sentinel과 닮은 텍스트여도 신호가 아니다(top-level만 신호). 자유답변은 결코 `yes`/`no` 전체 일치를 만들 수 없다(sentinel이 항상 선행).
  - 혼합(select multi): **행 순서는 계약으로 고정 — 모든 `User selected:` 행 → sentinel 블록**(sentinel 블록이 항상 마지막). (제약 4)
  - lsc_ask의 content는 기존 형태 불변 — ask는 게이트가 아니며 envelope 분기 대상이 아니다.
- `validateSelectOptions(options, recommended)` — **채널 공통 preflight(iter 4 신설 — P0-H·iter 5 순서 정밀화 — Minor-1)**: `performSelect`는 **unavailable fail-closed 처리(`src/ask.ts:141`) 후, fixture/UI dispatch(`:143-172`) 전에** 이 시맨틱 검증을 호출한다(명시 isError; 검증은 zod가 아닌 코어 순수 함수 — 단위 테스트 가능성 + zod 인스턴스화 깊이 억제). 현행 fixture-first 구조(`src/ask.ts:141-166` — unavailable `:141` → fixture 즉시 반환 `:143-166` → UI `:168-172`)를 보존한 채 검증을 표시행 생성에 묶어 두면 fixture 모드(=E2E)가 label 형식·예약어·중복·범위 가드를 전부 우회하는 해석이 합법이 되어 "E2E green / TUI isError" 발산이 생기므로(A/C 수렴), 검증 위치를 **dispatch 앞**으로 계약화한다 — 단 headless hard error(`src/ask.ts:5-8` seam 계약)는 현행대로 **preflight보다 선행**한다: P0-H가 요구한 parity는 fixture/UI 양 채널 공통이면 충족되고, preflight를 그보다 앞세우면 "채널 부재" 진단이 invalid-options 에러에 가려진다(A r4 §3.2 — precedence는 §3 AC1의 unavailable×invalid-label 테스트 1개로 고정). 표시 라벨 충돌 검사는 접미사·제어행 적용 후의 **표시 라벨 문자열만 파생**해 수행한다(표시행 객체/Map 할당 없음). 검증 항목:
  - **label 형식 가드(iter 3 신설·iter 5 규범 집합화 — envelope 단사성의 전제)**: label이 빈 문자열/공백-only, 비트림(선행·후행 공백), 또는 **mandatory break 7종(1-C 규범 정의 — VT·FF 포함) 중 어느 문자든 포함** → 명시 isError — 개행 label의 sentinel 행 위조(`"Review later\nUser provided free answer: approve"`가 기존 "시작" 가드를 통과하던 반례)와 selection 행 경계 파괴를, U+2028류 논리 분리자·interior VT/FF(`"Review\u000BUser selected: Accept"` — A r4 반례)까지 포함해 원천 차단(label은 모델 tool-call 인자라 임의 유니코드 유입이 가능한 표면 — A r3);
  - 호출자 options에 OTHER_OPTION/DONE_OPTION과 대소문자 무시 동일 라벨 → 명시 isError, 제어행별 정확 진단(단일 문구가 DONE을 free-text entry로 오서술하던 것 정정 — R-2): OTHER 충돌 "the free-text entry option is appended automatically — remove it from options" / DONE 충돌 "Done is a reserved control-row label — remove it from options" — **DONE은 전역 예약 택1(iter 5 — Minor-3)**: single select에서도 거부한다(조건부(`multi` 인자 추가) 대안 기각 — 옵션 배열의 유효성 판정을 모드 불변으로 유지해 preflight 시그니처·판정 결과가 `multi` 플래그에 흔들리지 않게 하고, 제어행 라벨 2종을 reserved namespace로 일괄 취급; 비용은 정확-일치 라벨 2개의 과잉거부뿐이며 명시 isError라 침묵 손실 없음);
  - 정본 라벨 중복(대소문자 무시) → 해석 무결성 에러;

## 4. DR (Deliberation Record)

### Principles (5)
1. **검증된 선행만 차용** — 같은 버전 SDK에 실행 중인 참조구현(builtin ask)의 패턴(Other append→editor 체인, 루프 multi, 조건부 Done, 병기 직렬화)을 이식하고 신규 발명을 최소화한다.
2. **원자적 co-evolution·클린 컷** — 코드·fixture·스킬·README가 한 사이클에 함께 바뀌고, 이중 계약(구/신 포맷 공존)을 만들지 않는다. green 검증·커밋 경계는 단일 cutover(§2 서두).
3. **게이트 결정성** — 자유답변은 결정이 아니다: **모델-visible content envelope**(정확 `yes`/`no` 전체 일치 + sentinel/opaque payload + 선택당 `User selected:` 행 — 문법 총칙은 1-C)·`confirmed:null` 구조체·스킬 분기 총론이 3중 방어선. 방어선은 모델이 실제로 받는 채널(content) 위에만 세우고(F5), 그 문법의 전제(입력 도메인·정규화·검증 위치)는 UI·fixture 양 ingress에서 동일하게 강제한다(iter 4 — 1-C/1-D/1-F; 정규화 집합은 UAX #14 규범 참조, 구현은 `canonicalizeFreeText` 단일 소유 — iter 5).
4. **매칭 표면 최소·안정** — 매칭은 정본 label로만(description·표시 접미사 불참여), 태깅 규약·기존 게이트 라벨 문자열 불변, **최종 표시 라벨 유일성과 envelope 예약 prefix·label 형식(non-empty·trimmed·single-line — mandatory break 7종)을 채널 공통 preflight로 검증해야 성립**(F2; iter 4-5).
5. **순수 코어 보존** — performX(channel, ui, params) 3-인자 + 명시적 타입 인자(TS2589) 관례 유지로 테스트 가능성을 지킨다.

### Decision Drivers (top 3)
1. **게이트 안전성**: 파괴적 승인([Land] 머지, [Hash Violation] 복원)의 오독 확률 0에 수렴 — R4 무조건성의 유일한 방어 체계. 방어는 모델이 볼 수 있는 채널에만 유효하다.
2. **파이프라인 무중단**: fixture v2 절체에도 기존 E2E 3종 그린 유지(인라인 fixture 3곳 동시 이관 + confirm content 보존) + 오늘도 잠재 파손인 select 게이트 결함 해소.
3. **구현 위험 최소**: 좁힘 3지점 국한 widening + 벤더 실증 패턴 — 미검증 UI 프리미티브 신설 없음.

### Decisions (설계 자유도 지점별 — 스펙 고정 사항은 제외)

**D1. 자유입력 진입 옵션의 라벨/위치/마커**
- **A(채택): 고정 상수 trailing** — `OTHER_OPTION = "Other (type your own)"`(벤더 문자열 동일), 항상 최종행(multi의 Done은 그 위, 체크 ≥1일 때만 — 벤더 순서 `tools/ask.ts:529-532`), 단일=radio 일반행/multi=markableCount 밖 제어행. 장점: 벤더·Claude Code 수렴 관례(C3/O38), 매칭·테스트 안정, fixture가 라벨을 참조할 필요 없음(kind가 경로 결정). 단점: 영어 고정 라벨(한국어 세션에서 이질감 — description 1줄로 보완).
- B(기각): 호출자 제공 라벨 파라미터(`freeInputLabel?`) — 장점: 로컬라이즈 가능. 단점: **무조건성 침식**(호출자가 오해 문구/빈 라벨로 형해화 가능 — R4 위반 벡터), 스키마 표면 증가, AC2와 정면 충돌. 무효.
- C(기각): `custom<T>()` 단일 위젯 병존 — 선행 없음(C12)·유지비·fixture 무관(스펙 Non-goal 재확인). 무효.

**D2. 구조체 직렬화 포맷(content·details·source)** (iter 2 재규정 — F5 반영; iter 3 multi 직렬화 재보정; iter 4 canonical 저장 보강)
- **(채택): content = 모델-facing 결정 정본 envelope, details = 테스트/UI/이벤트 관측용 구조 정본.** content는 사람이 읽는 병기 텍스트이되 게이트 결정이 파싱 가능한 고정 형태(1-C: 정확 `yes`/`no` 단독 | 선택당 `User selected:` 행 반복 | sentinel+opaque payload 블록, 혼합은 모든 selection 행 → sentinel 블록)를 계약으로 갖는다. 장점: provider가 content만 전송하므로(F5) 결정 계약이 실제 전달 채널 위에 서고, 벤더 계약 차용(O57), 스킬(LLM) 소비 자연, **enforcement E2E 텍스트 단언(F3) 무파손**. 단점: 두 표현의 정합을 테스트로 잠가야 함(→ envelope 정확 문자열 단위 테스트, §3 AC3/AC4). iter 1의 "details가 정본, content는 투영" 규정은 **폐기** — 모델에게 details는 존재하지 않으므로 그 규정은 게이트 방어선을 전달되지 않는 채널에 세우는 것이었다. **iter 3 재보정**: multi 직렬화를 콤마 결합 단일 행에서 **선택당 header 행 반복**으로 교체(허용 label 공간에서 비단사였던 반례 소거) — JSON 배열 대안(`User selected: ["…"]`)도 문법을 닫지만 본 결정이 기각한 JSON-in-content를 부분 재도입하고 E2E 텍스트 단언 형태·가독성에서 열위라 행 반복을 채택(critic 권장안과 합치; 1-C 택1 근거). **iter 4 보강**: freeText는 ingress에서 line-break canonical `\n` 정규화 후 직렬화·저장하며 `details.freeText`도 canonical이다(content·details 단일 진실 — raw 병행 보존 기각, 1-C 저장 계약/P0-G④; 단사성 주장은 canonicalized text 기준으로 한정). **iter 5 보강**: 정규화 집합은 UAX #14 mandatory break 7종(VT/FF 편입 — P0-J), 구현은 `canonicalizeFreeText` 단일 소유·양 ingress 공통 순서(`src/fixtures.ts` export — P0-K).
- 대안(기각): `JSON.stringify(details)`를 content로 — 기계적 일관성은 있으나 스킬 프롬프트 가독성 저하 + E2E 텍스트 단언 파손 + 벤더 관례 이탈. 무효.
- source **(채택): 기존 `"fixture"|"ui"` 출처 의미 유지** — 응답 종류는 selections/freeText/confirmed 필드 존재로 완전 판별 가능하므로 종류 판별자 중복 도입은 두 진실 원천(불일치 버그 벡터)만 만든다. 출처는 다른 필드에서 파생 불가(E2E/디버깅 가치).
- 대안(기각): source = 응답 종류(`"options"|"free"|"mixed"`) — 파생 가능 정보의 중복 + 기존 details 계약 파괴. 무효.

**D3. fixture v2 스키마 형태** (iter 2 채택안 교체)
- **(채택): response-semantic tagged union** — `{kind:"free-text"|"selection"|"selection-index"|"confirmation"}`(1-F). `free-text`는 **도구 불문 소비**로 도구 선택의 런타임 비결정성(인터뷰 질문이 select로도 ask로도 발화 — `src/fixtures.ts:29-32` 실측)을 흡수하고, 나머지 kind는 해당 의미의 도구만 소비한다. 장점: **모순 조합(`confirm`×`freeText` 등)이 parse-time에 불가능** — 승인과 반대 의사가 한 body에 공존해 승인이 침묵 우선하는 클래스가 소멸; kind별 검증이 자기 서술적; catch-all 결함(C5)은 "명확 에러 + 명시 규칙"으로 동일 해소. 단점: JSON이 약간 장황(+`"kind":…` 1필드), 마이그레이션 문서 1절 추가 — 게이트 무결성 대비 수용. **iter 3 보강**: "parse-time에 불가능" 주장이 성립하려면 variant 필드 조합 거부만으로는 부족하고 **rule/default의 미지 키 exact allowlist**(1-F)가 필요하다 — 현행 known-field projection 승계 시 stale `response`가 침묵 폐기되는 반례가 주장을 무너뜨림(A/C 수렴). **iter 4 추가 보강**: 키 조합에 더해 **값·최상위 도메인**도 닫는다 — nonblank freeText(P0-F, canonical 정규화-후-trim)·top-level exact allowlist(P1-I)로 "불법 fixture 상태의 parse-time 소거" 주장이 blank 값·top-level 오타(`defualt`)까지 성립한다.
- 기각 1: **flat-body + 도구별 필드 해석**(iter 1 채택안) — `{selections?/optionIndex?/freeText?/confirm?}` 전부 optional + "답 필드 ≥1" 검증. 작성은 간결하나 `{"match":"^\\[Land\\]","confirm":true,"freeText":"Do not merge yet"}`가 파서를 통과하고 confirm 우선순위로 [Land]를 승인하며 반대 텍스트를 버린다 — Principle 3 자기모순(리뷰 2건 수렴 지적). 무효.
- 기각 2: tool-kind union(`{kind:"select", …}`) — 도구 선택 비결정성에 취약(kind 불일치 시 전 규칙 무효 — 오늘의 결함을 형태만 바꿔 재생산). 무효.
- 기각 3: v1 확장(`response` 유지 + 필드 추가) — R7 클린 컷 위반 + catch-all 모호성 존속. 무효.
- 부속: **`selection-index` kind 존치** — "예측 불가 라벨 중 n번째 선택"(동적 옵션 — §2.5류)은 위치 지정 없이 표현 불가. 단 iter 1의 "selections 해석 실패 시 optionIndex 폴백"(한 규칙 내 조합)은 union으로 **소멸** — 명시성 우선, 폴백이 필요했던 라벨 드리프트 케이스는 selection-index 규칙으로 직접 표현. **default의 free-text 금지는 parse-time 검증으로 승격**(1-F) — default는 파괴적 게이트를 포함한 전 미매칭 질문에 닿으므로.

**D4. confirm 재구성의 Yes/No 라벨 처리**
- **(채택): 영어 "Yes"/"No" 고정 + description 생략 + recommended/timeout 없음 + 커서 기본 첫 행** — 라벨은 태깅 규약과 동급의 시스템 식별자(스킬 분기·스모크 기대값 안정), 자명 라벨엔 description이 노이즈(C14). parseYesNo는 삭제(UI=라벨 직결, fixture=`confirmation` 명시 — 사어).

**D5. 작성 가이드 인코딩 위치**

**D6. recommended 오염 방지 기제** (iter 2 재규정 — "index 역매핑"이 아니라 검증된 display-label lookup)
- **(채택): 표시 라벨 유일성 검증 + `Map<표시 라벨, 정본 라벨>` 해석** — SDK는 index가 아니라 표시 라벨 문자열만 반환하므로(F2 — `hook-selector.ts:248-249, 660-661`) 해석은 본질적으로 label lookup이다. 표시 계층(접미사 포함)과 데이터 계층(정본 label)을 분리하고, **접미사·제어행 적용 후 최종 표시 라벨 집합의 유일성(대소문자 무시)을 검증**해 lookup의 성립 조건을 강제한다(`"A"`+`"A (Recommended)"`+`recommended:0` → 두 표시행이 동일 문자열 — 검증 없이는 해석 모호). strip 연산이 없어 이중 strip·우연 접미사 병리는 여전히 부재하며, "오염 클래스 소멸" 주장은 **유일성 검증이 있을 때만 참**이므로 검증을 채택안의 일부로 명시한다(iter 4: 이 검증은 validateSelectOptions로 채널 공통 preflight화 — 1-C; iter 5: 실행 위치는 unavailable 후·fixture/UI dispatch 전 — Minor-1). envelope 예약 prefix 가드·label 형식 가드(1-C)도 같은 위장 클래스의 content 계층 방어. AC6의 "append-then-strip 검증"은 오염 부재 불변식 + adversarial 충돌 케이스 단언으로 충족. SDK는 16.4.0 exact pin(`package.json:19`) — 향후 업그레이드 시 label-반환 계약 재고정은 Follow-ups.

## 5. ADR

- **Decision**: 3도구를 `ctx.ui.select`/`ctx.ui.editor` 조합 위에서 재구성한다 — 자유입력은 auto-append trailing 옵션→editor 체인(벤더 이식, editor Esc는 select 복귀), multi는 select 재호출 토글 루프(F1, Done은 체크 ≥1일 때만 — builtin 동등), 반환은 **모델-facing content envelope(정확 `yes`/`no` 단독 | 선택당 `User selected:` 행 반복 | 자유답변 sentinel+들여쓴 opaque payload, 혼합은 selection 행들 → sentinel 블록; label은 non-empty·trimmed·single-line(UAX #14 mandatory break 7종 — LF·VT·FF·CR·NEL·LS·PS) 강제, freeText는 nonblank + ingress에서 단일 소유 `canonicalizeFreeText`(`src/fixtures.ts` export, 7종 → canonical `\n`, CRLF 선행 접기) 정규화 — content·details 공통)를 결정 정본으로, `{selections|confirmed, freeText?, source}` details를 관측 정본으로** 하는 2계층(F5), select 시맨틱 검증은 **채널 공통 preflight(validateSelectOptions — unavailable fail-closed 후·fixture/UI dispatch 전)**로 수행하고 recommended는 표시 라벨 유일성 검증 + Map lookup으로 오염 차단, fixture는 `version: 2` **response-semantic tagged union**으로 클린 컷(v1·모순 조합·미지 키(rule/default/top-level)·free-text default·blank freeText는 parse-time 명확 에러 — exact allowlist), 품질 규칙은 `.describe` 요약 + pre-craft SSOT 가이드 2계층(+대응표)으로 인코딩하며, 전체는 단일 원자 cutover로 커밋한다.
- **Drivers**: §4 top 3(게이트 안전성 / 파이프라인 무중단 / 구현 위험 최소).
- **Alternatives considered**: 호출자 제어 자유입력 라벨(D1-B), custom<T>() 위젯(D1-C), JSON content·종류형 source·콤마 결합/JSON 배열 multi 직렬화·details raw 병행 보존(D2·1-C), flat-body·tool-kind union·v1 확장·fixture blank 허용·top-level 전부-무시 승계(D3·1-F), 로컬라이즈 Yes/No·parseYesNo 존치(D4), 가이드 3중복·shared 파일(D5), 문자열 strip(D6), 지시형 invalid-call E2E·신규 E2E 파일·cap-도달 의존 발화(D7), 2분할·산문 선행 커밋·test-infra 준비 커밋 분리(D8), canonicalizer 중립 모듈 신설·DONE 조건부(multi 인자) 예약·preflight 최선행(unavailable 전) 배치(1-C, iter 5) — 각 무효화 근거는 §4·1-C.
- **Why chosen**: 유일하게 (i) R4 무조건성을 호출자로부터 지키고, (ii) 도구 선택의 런타임 비결정성(인터뷰)에 견디며, (iii) 기존 E2E 텍스트 단언·순수 코어 관례·게이트 라벨 식별자를 전부 보존하면서, (iv) **게이트 방어선을 모델이 실제로 받는 채널(content) 위에 닫힌 문법으로 세우고 — 그 문법의 전제인 입력 도메인·정규화·검증 위치까지 양 ingress 공통으로 — 불법 fixture 상태를 파서 단계에서 소거**하는 조합이기 때문.
- **Consequences**: ① `ConfirmUI`·`parseYesNo`·`placeholder` 소멸(소비자 전수 이관 — `test/ask.test.ts:5` import 포함); ② confirm에 취소 경로 신설(기존 `ui.confirm`은 불가) — 스킬은 게이트 미결로 처리; ③ v1 answers.json은 어디서든 즉시 명확 에러(의도된 시끄러운 파손) — 저장소 내 3곳 동시 이관 필수, 커밋은 단일 cutover(D8); ④ content 계약 변화(select가 라벨 원문 1행 → `User selected:` envelope 병기)로 스킬의 정확-라벨 소비는 **content의 `User selected:` 행 파싱으로 상향**(SKILL 개정에 반영; details.selections는 테스트·이벤트 관측용 — 모델 분기에 사용 금지, F5); ⑤ `approval: "read"` 유지 — 부작용 표면 불변; ⑥ 옵션 2-4·파트당 1-2줄 상한은 compact 발동 확률·심도를 낮추지만 배제하지 않음(F4) — 발동 시에도 커서 이동으로 description 열람 가능, TUI 스모크 ⑦로 관찰; ⑦ envelope prefix 2종(`User selected:`/`User provided free answer:`)의 stem과 제어행 라벨 2종(OTHER/DONE — **DONE은 single select 포함 전역 예약, iter 5 택1**)은 옵션 label의 **예약 네임스페이스**가 되고, label 형식(non-empty·trimmed·single-line — iter 5에 UAX #14 mandatory break 7종(VT/FF 편입)으로 규범화)도 도구 검증 계약이 되며, 검증은 채널 공통 preflight(unavailable 후·dispatch 전)라 fixture 모드에도 동일 적용된다(iter 3-5). **근거의 정직한 기록(iter 5 — Minor-3)**: stem `startsWith` 거부와 DONE 전역 예약은 envelope **단사성의 필수조건이 아니다** — serializer가 항상 header prefix를 선행 부착하고 label이 single-line이라 형식 문법은 이 가드 없이도 닫힌다(A r4 형식 논증 확증). 유지 근거는 reserved-namespace / LLM 오독 defense-in-depth: 결정 header와 동형의 텍스트가 옵션·제어행으로 노출되는 것 자체가 모델-facing 오독 표면이다. 그 대가로 `User selected: Manual review` 류 합법 label의 과잉거부를 수용한다 — 실측 저장소 내 해당 stem 사용 label 0건, 거부는 명시 isError라 침묵 손실이 없으며, 회피는 label 자구 1회 수정으로 충분; ⑧ 테스트 표면 확장 — devDep `zod`(mock-pi 캡처용, `zod/v4` import — manifest 2종 cutover 동반) + e2e-helpers details 보존 확장; ⑨ fixture rule-local 임의 metadata 불허(exact allowlist) — 주석류는 top-level `_` prefix 키(`_note`/`_warning` 등 임의 `_` 키)로만, 그 외 top-level 미지 키도 거부(`defualt` 오타 침묵 무시 결함 동반 해소, P1-I); ⑩ freeText 값 계약(iter 4-5) — blank(canonical 정규화-후-trim 기준 빈) 거부·line-break는 canonical `\n`으로 정규화 저장되어 **raw line-ending 종류(비-canonical raw 분리자 형태 전부 — CRLF 시퀀스 + LF 외 mandatory break 6종 CR/VT/FF/NEL/LS/PS; 정규화 산출물인 LF만 보존)는 content·details 어디에도 보존되지 않는다**(단일 진실 택1, P0-G④ — A r3 tradeoff 표의 미결정을 플랜이 결정; A r4 tradeoff 표의 "raw separator 종류 비보존"도 동일 수용).
- **Follow-ups** (본 범위 밖, 기록만): suffix 계열 비대칭(craft 3종 vs pre/post 5종) 정리; pre-craft `:131` 무태그 confirm 태깅; editor title 장문 캡(벤더 `tools/ask.ts:155` 참고) 필요 시 후속; SDK 업그레이드 시 label-반환 계약 host-level 재고정(D6); craft 도구 자신(lsc_verify_hash/lsc_run_tests/lsc_restore_tests)의 `details.passed`/`details.violations` SKILL 서술 정리(F5와 동형 서술이나 별개 도구 계약 — content가 판정 텍스트를 mirror해 실동작, C iter 2 open question 기록).
